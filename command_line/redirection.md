# Redirection

## 1. What Is Redirection?

**Redirection** is a shell feature that changes where a command receives its input or sends its output.

By default:
- Standard input comes from the keyboard.
- Standard output is displayed on the terminal.
- Standard error is displayed on the terminal.

Redirection allows us to send input or output to files instead of using the default devices.

### Why Is Redirection Useful?

- Save command output to a file.
- Capture error messages for troubleshooting.
- Read input from an existing file.
- Keep terminal output organized.
- Automate command-line tasks.

---

## 2. The Three Standard Streams

Linux and Unix shells use file descriptors to identify the three standard input/output streams.

| File descriptor | Stream | Purpose | Default destination/source |
|---|---|---|---|
| `0` | Standard input (`stdin`) | Receives input | Keyboard |
| `1` | Standard output (`stdout`) | Produces normal output | Terminal |
| `2` | Standard error (`stderr`) | Produces error messages | Terminal |

**Key concept:** File descriptors are numbers that identify open input/output streams.

---

## 3. Standard Input Redirection

Standard input redirection allows a command to read input from a file rather than directly from the keyboard.

The operator is:

```bash
<
```

### Example: Read a file using standard input

```bash
cat < input.txt
```

**How it works:**
1. `< input.txt` redirects standard input from `input.txt`.
2. `cat` reads the contents from standard input.
3. The contents are displayed in the terminal.

This is equivalent in purpose to:

```bash
cat input.txt
```

### Example: Create a text file from keyboard input

```bash
cat > input.txt
```

Type your text into the terminal. When you have finished, press `Ctrl + D` to signal the end of input.

**Important distinction:** The `>` operator in this command redirects standard output to a file. It is not standard input redirection.

---

## 4. Standard Output Redirection

Standard output redirection sends normal command output to a file instead of displaying it in the terminal.

The operator is:

```bash
>
```

### Example: Save a directory listing

```bash
ls -l > output.txt
```

**How it works:**
1. `ls -l` produces a detailed directory listing.
2. `>` redirects standard output to `output.txt`.
3. The shell creates the file if it does not exist.
4. If the file already exists, its previous contents are overwritten.

To inspect the saved output:

```bash
cat output.txt
```

### Append output instead of overwriting

Use `>>` to append output to the end of a file.

```bash
ls -l >> output.txt
```

Unlike `>`, the `>>` operator preserves the existing contents and adds the new output.

| Operator | Behaviour |
|---|---|
| `>` | Creates or overwrites a file |
| `>>` | Creates a file if needed, or appends to it |

**Warning:** Using `>` on an existing file can permanently replace its contents.

---

## 5. Standard Error Redirection

Standard error contains error messages generated by commands.

Its file descriptor is `2`.

Use `2>` to redirect standard error to a file.

### Example: Save an error message

```bash
ls -l /bin/usr 2> error.txt
```

If `/bin/usr` does not exist, `ls` generates an error message.

**How it works:**
1. `ls -l /bin/usr` attempts to list the specified path.
2. `2>` redirects standard error to `error.txt`.
3. The error message is saved to the file instead of being displayed in the terminal.

To read the error:

```bash
cat error.txt
```

The exact error message depends on the command and environment.

### Append error messages

```bash
ls -l /bin/usr 2>> error.txt
```

This appends new error messages to the existing file instead of overwriting it.

---

## 6. Redirect Standard Output and Standard Error Together

Sometimes a command produces normal output and may also produce errors. You can redirect both streams to the same file.

### Example

```bash
ls -l /bin/usr > error_output.txt 2>&1
```

**How it works:**
1. `> error_output.txt` redirects standard output to the file.
2. `2>&1` redirects standard error to the same destination as standard output.
3. Both streams are written to `error_output.txt`.

The order matters because `2>&1` copies the current destination of standard output.

To inspect the file:

```bash
cat error_output.txt
```

### Alternative syntax in Bash

```bash
ls -l /bin/usr &> error_output.txt
```

In Bash, `&>` redirects both standard output and standard error to the same file.

The more explicit `> error_output.txt 2>&1` form is widely used in shell scripts.

## 7. Quick Reference Table

| Command | Purpose |
|---|---|
| `cat < input.txt` | Read a file through standard input |
| `cat > input.txt` | Write keyboard input to a file |
| `ls -l > output.txt` | Save normal output, overwriting the file |
| `ls -l >> output.txt` | Append normal output |
| `ls -l /bin/usr 2> error.txt` | Save error messages |
| `ls -l /bin/usr 2>> error.txt` | Append error messages |
| `ls -l /bin/usr > output.txt 2>&1` | Redirect both streams to one file |
| `cat output.txt` | Display a file's contents |
| `less error.txt` | View a file one screen at a time |

## 8. Pipes vs. Redirection

Pipes and redirection both connect command-line operations, but they serve different purposes.

### Pipe (`|`)

Passes the output of one command as input to another command.

```bash
cat input.txt | wc -w
```

This counts the words in `input.txt`.

### Redirection (`>`)

Sends command output to a file.

```bash
ls -l > output.txt
```

This saves the directory listing to `output.txt`.

### Main differences

| Feature | Pipe (`|`) | Redirection (`>`) |
|---|---|---|
| Main purpose | Connect commands | Change input/output destination |
| Destination | Another command | A file |
| Example | `cat input.txt \| wc -w` | `ls > output.txt` |

---

## 9. Common Mistakes

- **Confusing `<` and `>`:** `<` redirects input from a file; `>` redirects output to a file.
- **Overwriting important data:** `>` replaces the existing contents of a file. Use `>>` to append.
- **Forgetting file descriptor `2`:** Use `2>` when you want to redirect error messages.
- **Incorrect command order:** Use `> output.txt 2>&1` when both streams should go to the same file.
- **Assuming every error is standard output:** Error messages normally use standard error, so `>` alone will not capture them.
- **Using `cat > file.txt` without understanding it:** This waits for keyboard input and overwrites the target file when the redirection is opened.

## 11. Key Takeaways

- Redirection changes where a command receives input or sends output.
- File descriptor `0` represents standard input.
- File descriptor `1` represents standard output.
- File descriptor `2` represents standard error.
- `<` redirects input from a file.
- `>` redirects output and overwrites an existing file.
- `>>` appends output to a file.
- `2>` redirects error messages.
- `2>&1` redirects standard error to the current destination of standard output.
- Redirection is an important skill for Linux, shell scripting, debugging, automation, and CI/CD workflows.
